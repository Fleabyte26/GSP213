# GSP213 – VPC Networking Fundamentals: Web Servers, Tagged Firewalls and IAM Roles

Everything in this tutorial is done from Cloud Shell, including the steps the lab does in the Console. The checker only looks at the resources, so the result is the same.

## Known lab traps (read first)

1. The lab deletes the firewall rule at the end. Make sure "Create the tagged firewall rule" is green before Task 3.
2. Once you activate the service account, Cloud Shell runs every command as that account. It can't change IAM roles, so the Security Admin swap below runs as your student account with `--account`.
3. IAM changes take up to 1–2 minutes to apply. If the delete still says permission denied after the role swap, wait a minute and run it again.
4. The "Install Nginx" check needs the startup scripts to finish, which takes about 1–2 minutes after the VMs are created.
5. The zone changes per lab instance. Find it in the Task 1 table (the Zone row).
6. `#!/bin/bash` contains a `!`, which Cloud Shell can treat as a history command when you paste. The blocks start with `set +H` to prevent that.

## Setup (edit to match your lab)

Change the zone on the first line to the Zone in your lab's Task 1 table.

```bash
echo us-east1-b > ~/zone
gcloud config get-value project > ~/project
gcloud config get-value account > ~/student
head ~/zone ~/project ~/student
```

## Task 1 – Create the web servers

Block 1 – blue server (with the web-server tag):

```bash
set +H
cat > ~/blue.sh <<'EOF'
#!/bin/bash
apt-get update
apt-get install -y nginx-light
echo "<h1>Welcome to the blue server!</h1>" > /var/www/html/index.nginx-debian.html
EOF
gcloud compute instances create blue --zone=`cat ~/zone` --machine-type=e2-medium \
  --image-family=debian-12 --image-project=debian-cloud \
  --tags=web-server --metadata-from-file=startup-script=/home/`whoami`/blue.sh
```

Check my progress: Create the blue server

Block 2 – green server (no tag):

```bash
set +H
cat > ~/green.sh <<'EOF'
#!/bin/bash
apt-get update
apt-get install -y nginx-light
echo "<h1>Welcome to the green server!</h1>" > /var/www/html/index.nginx-debian.html
EOF
gcloud compute instances create green --zone=`cat ~/zone` --machine-type=e2-medium \
  --image-family=debian-12 --image-project=debian-cloud \
  --metadata-from-file=startup-script=/home/`whoami`/green.sh
```

Check my progress: Create the green server

Wait about 2 minutes for nginx to install, then click Check my progress: Install Nginx and customize the welcome page.

## Task 2 – Firewall rule and HTTP tests

Block 1 – tagged firewall rule:

```bash
gcloud compute firewall-rules create allow-http-web-server --network=default --direction=INGRESS \
  --action=ALLOW --rules=tcp:80,icmp --target-tags=web-server --source-ranges=0.0.0.0/0
```

Check my progress: Create the tagged firewall rule

Block 2 – test-vm:

```bash
gcloud compute instances create test-vm --machine-type=e2-micro --subnet=default --zone=`cat ~/zone`
```

Check my progress: Create a test-vm

Block 3 – save the IPs (the lab uses export variables; these files do the same job):

```bash
gcloud compute instances describe blue --zone=`cat ~/zone` --format='get(networkInterfaces[0].accessConfigs[0].natIP)' > ~/blue-ext
gcloud compute instances describe green --zone=`cat ~/zone` --format='get(networkInterfaces[0].accessConfigs[0].natIP)' > ~/green-ext
gcloud compute instances describe blue --zone=`cat ~/zone` --format='get(networkInterfaces[0].networkIP)' > ~/blue-int
gcloud compute instances describe green --zone=`cat ~/zone` --format='get(networkInterfaces[0].networkIP)' > ~/green-int
head ~/blue-ext ~/green-ext ~/blue-int ~/green-int
```

Block 4 – external tests from Cloud Shell. Blue answers; green times out because it has no tag:

```bash
curl -m 3 http://`cat ~/blue-ext`
curl -m 3 http://`cat ~/green-ext`
```

Block 5 – internal tests from test-vm. Both answer, because default-allow-internal permits traffic inside the VPC:

```bash
gcloud compute ssh test-vm --zone=`cat ~/zone` --quiet --command="curl -s http://`cat ~/blue-int`; curl -s http://`cat ~/green-int`"
```

The first time, it generates an SSH key. That's normal.

## Task 3 – Network Admin vs Security Admin

Block 1 – grant Compute Network Admin to the network-admin service account:

```bash
gcloud projects add-iam-policy-binding `cat ~/project` \
  --member=serviceAccount:network-admin@`cat ~/project`.iam.gserviceaccount.com \
  --role=roles/compute.networkAdmin --condition=None
```

Check my progress: Create a Network-admin service account

Block 2 – create a key and act as the service account:

```bash
gcloud iam service-accounts keys create ~/credentials.json --iam-account=network-admin@`cat ~/project`.iam.gserviceaccount.com
gcloud auth activate-service-account --key-file=/home/`whoami`/credentials.json
gcloud compute firewall-rules list
gcloud compute firewall-rules delete allow-http-web-server --quiet
```

The list works. The delete fails with a "compute.firewalls.delete permission" error. That's the point: Network Admin can't touch firewall rules.

Block 3 – swap the role to Security Admin (runs as your student account):

```bash
gcloud projects remove-iam-policy-binding `cat ~/project` --account=`cat ~/student` \
  --member=serviceAccount:network-admin@`cat ~/project`.iam.gserviceaccount.com \
  --role=roles/compute.networkAdmin --condition=None
gcloud projects add-iam-policy-binding `cat ~/project` --account=`cat ~/student` \
  --member=serviceAccount:network-admin@`cat ~/project`.iam.gserviceaccount.com \
  --role=roles/compute.securityAdmin --condition=None
```

Block 4 – wait for IAM to apply, then delete as the service account:

```bash
sleep 60
gcloud compute firewall-rules delete allow-http-web-server --quiet
```

If it still says permission denied, wait another minute and run the delete line again.

Block 5 – switch back to your student account and confirm blue is now blocked:

```bash
gcloud config set account `cat ~/student`
curl -m 3 http://`cat ~/blue-ext`
```

The curl should time out, because the firewall rule is gone.
